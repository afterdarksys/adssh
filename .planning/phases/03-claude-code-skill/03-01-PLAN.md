**Section 3: Tool Selection Decision Rule (per D-09)**
- Heading: `## Tool Selection`
- Decision table:
  | Situation | Use |
  Need cloud namespace access with arguments | eval_starlark
  Single zero-argument cloud function | cloud_query (simpler)
  Multi-step Starlark logic, loops, combining results | eval_starlark
  POSIX pipeline: grep, awk, sed, file ops, system commands | run_shell
  Anything easier as a shell one-liner | run_shell
  Check active SSH sessions | list_sessions
  Run something in a container without leaving artifacts | container_exec
  Review activity or debug a policy denial | audit_log
- Key insight: cloud_query is a convenience shortcut for eval_starlark when calling a zero-argument function. For anything with arguments or multi-step logic, use eval_starlark.

**Section 4: Tool Reference (per D-07)**
For EACH of the 6 tools, create a subsection with:
- Tool name as heading (e.g., `### eval_starlark`)

- Parameter table: | Parameter | Type | Required | Default | Description |

The 6 tools and their verified schemas:

**eval_starlark**: param `code` (string, required). Returns plain text `output: <print output>\nresult: <return value>`. Example: query AWS instances via Starlark `aws["list_instances"]()`.

**run_shell**: param `command` (string, required). Returns plain text `exit_code: <int>\nstdout: <string>\nstderr: <string>`. Note: uses mvdan.cc/sh POSIX shell, NOT bash — avoid `[[`, bash arrays, `(( ))`. Example: `ls -la /var/log | head -5`.

**list_sessions**: no params. Returns JSON array of session ID strings, e.g. `["session-abc123"]` or `[]`. Example: check what sessions are active.

**cloud_query**: params `namespace` (string, required: aws|gcp|oci|cloud), `function` (string, required). Returns string representation of Starlark return value. CRITICAL: calls function with NO arguments — use eval_starlark if function needs args. Example: `namespace="aws", function="list_buckets"`.

**container_exec**: params `image` (string, required), `cmd` (string, required — JSON array or single string). Returns JSON `{"session_id":"...","exit_code":0,"stdout":"...","stderr":"...","duration_ms":1234}`. Requires Docker daemon. Example: `image="ubuntu:22.04", cmd='["cat","/etc/os-release"]'`.

**audit_log**: params `limit` (number, optional, default 50), `filter` (string, optional). Returns newline-separated log lines or `(no audit log entries)`. Example: `filter="denied"` to see policy denials.

- Heading: `## Workflows`

Workflow 1: "Investigate SSH Sessions + Cloud Cost Query"

2. container_exec → spin up ephemeral container to run diagnostic
3. audit_log → confirm commands were logged

Workflow 3: "Debug a Policy Denial"

2. audit_log with filter="denied" → see what was blocked
3. Explain the denial and suggest policy file edit

- run_shell is POSIX shell via mvdan/sh, not bash (avoid bash-specific syntax)
